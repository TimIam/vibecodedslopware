## Adding a project
1. Put it in its own folder with an `index.html`.
2. Add a card to `index.html` linking to it **with a trailing slash** (`/my-thing/`), so relative paths resolve. The page sorts the cards itself (latest update, first release, popular, A–Z), so where it goes in the file does not matter.
3. Every standalone HTML page, including full-screen games and demos, uses the fixed `.site-topbar` home/support navigation and loads `/site-nav.css` and `/site-nav.js`. Reuse the verified Buy Me a Coffee destination (`https://buymeacoffee.com/twilliamja0`); keep page-specific controls in the bar. Matrix background/embed surfaces retain their navigation-free rendering.
4. After committing, run `node tools/versions.mjs` and commit what it writes (`apps.js`, `v/`, `vercel.json`). That gives the card its version number, dates, prompts, tokens and the squares linking to older versions. Every commit that changes just one game is a version; older ones are served from `/v/<slug>/<n>/`, where `v/` holds only the files that differ from today and `vercel.json` sends every other path to the live folder. A new game made in Claude Code needs its session id added to `SESSIONS` in that script for prompts and tokens; visits come from `tools/popularity.json`, refreshed by hand from Vercel Observability.

## Local dev
The static pages work from any file server. To run the API too:

```bash
npm install
echo ANTHROPIC_API_KEY=sk-ant-... > .env.local   # or: npx vercel env pull .env.local
npm run dev                                       # http://localhost:3131
```

`tools/dev.mjs` serves the site and mounts `api/*.js` the way Vercel does (Web `Request` in, streamed `Response` out). It is not part of the deploy.

## Deploy
Hosted on Vercel (project `vibecodedslopware`). Pushing to GitHub does **not** deploy; deploy with the CLI from this folder:

```bash
vercel link --yes --project vibecodedslopware   # once per machine
vercel deploy --prod --yes
```

`vercel deploy` replaces the whole site with this folder's contents. It uploads git-ignored files too, so anything that must stay off the public site goes in `.vercelignore` (currently `matrix/mac/` and local secrets). If anything was deployed from somewhere else, pull it into this folder and commit it first.

`api/reading.js` needs `ANTHROPIC_API_KEY` set on the Vercel project (Settings → Environment Variables, or `npx vercel env add ANTHROPIC_API_KEY production`). Without it the psychic page loads but every reading fails with "the crystal ball isn't plugged in".

### Turning on the shop
Until all three secrets below are set, the shop page and try-on work but checkout reads "Checkout opens soon".

1. **Printful**: create a store of type *Manual order platform / API*, then Developer Portal → create a private token for that store with the orders scope → `PRINTFUL_API_TOKEN`. (An account-level token also needs `PRINTFUL_STORE_ID`.) Add a billing card in Printful; it charges you the base cost when an order goes to production.
2. **Stripe**: Developers → API keys → secret key → `STRIPE_SECRET_KEY`. Developers → Webhooks → add endpoint `https://vibecodedslopware.com/api/shop-webhook` for `checkout.session.completed` and `checkout.session.async_payment_succeeded` → its signing secret → `STRIPE_WEBHOOK_SECRET`.
3. `npx vercel env add <NAME> production` for each, then deploy.

Orders arrive in Printful as **drafts** to approve by hand. Once a few have gone through cleanly, set `PRINTFUL_CONFIRM=1` to send them straight to production. Sales tax isn't collected (Stripe Tax is off); turn on `automatic_tax` in `api/shop-checkout.js` if you register for it.
